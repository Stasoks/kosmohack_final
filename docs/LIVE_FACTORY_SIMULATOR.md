# Симуляция живого производства

Demo-профиль TRACE-Q включает отдельный сервис `factory-simulator`. Он хранит сессии в памяти процесса, получает снимок активной ревизии маршрута через API TRACE-Q и отправляет канонические P0-события в обычный endpoint `/api/v1/events`.

Симулятор не подключается к PostgreSQL, не импортирует SQLAlchemy-модели backend и не принимает решений контролёра. Для чтения маршрутов, изделий и несоответствий используется отдельная учётная запись `factory-simulator` с ролью `simulator_reader`. Для событий применяются зарегистрированные demo-источники MES, Vision QC и оборудования. Поле `source.sequence` намеренно не отправляется.

## Режимы

- **Штатное прохождение** — регистрация изделия, операции и успешный контроль по снимку маршрута.
- **Дефект и доработка** — детерминированный дефект `surface_crack`; сессия ждёт решения контролёра, затем выполняет связанную доработку и ждёт проверки её результата.
- **Предупреждение оборудования** — в производственный поток добавляется событие `machine.state`, не объявляемое причиной дефекта.

Дефект остаётся во внутреннем состоянии изделия до успешной доработки и повторного контроля. Маршрут фиксируется при создании сессии, поэтому последующее редактирование маршрута не меняет уже запущенный поток.

## Управление

В Streamlit откройте **Симуляция производства**. Можно создать сессию, запустить, поставить на паузу, продолжить, выполнить один шаг, остановить, сбросить или удалить её. Состояние хранится в сервисе, поэтому обновление страницы Streamlit не останавливает симуляцию.

HTTP API сервиса:

- `GET /health`;
- `GET|POST /sessions`;
- `GET|DELETE /sessions/{id}`;
- `POST /sessions/{id}/start|pause|resume|step|stop|reset`.

Сервис существует только в `compose.demo.yaml` и не входит в production compose.
